# Normalize 与 Kraken 计算结果对比测试设计

## 目标

基于 `src/algorithm/run.cpp` 中的 `OpenOceanKraken::Normalize`，建立一个可重复执行的端到端对照测试。测试让 OOK 与 Fortran Kraken 使用同一声学环境完成模态求解，从双方生成的 MOD 文件中比较 `Normalize` 可观测结果，并永久保留输入环境、运行脚本和对比报告。

本测试验证当前实现与工作区中的 Fortran Kraken 基准实现一致，不修改 `Normalize` 的生产逻辑，也不为测试暴露仅存在于函数内部的中间变量。

## 基准实现与测试边界

- 被测实现：`OOK/src/algorithm/run.cpp` 中的实数 `Normalize`。
- 数值基准：`krakenFortran/kraken/kraken.f90` 中的 Fortran `Normalize`，由 `kraken.exe` 执行。
- 执行边界：从同一个 `.env` 文件开始，分别完成环境读取、特征值求解、逆迭代、归一化和 MOD 输出。
- 主要归一化观测量：MOD 文件中的深度网格、归一化模态函数 `Phi` 和归一化后修正的复模态波数。
- 非目标：不单独验证 `BCImpedance`、`InverseIteration` 或 `ScatterLoss` 的所有分支；不修改 Fortran 程序以输出 `RN`、`ScaleFactor`、`Slow`、`VG` 或 `Perturbation_k`。

由于测试经过完整求解链路，失败可能来自归一化上游。报告必须分别列出网格、模态波数和模态函数差异，不能在没有进一步证据时把所有端到端差异都归因于 `Normalize`。

## 测试环境

新增并保留一个专用的、单频、单声学层环境：

`for_test/fixtures/normalize/normalize_reference.env`

环境采用常用的真空上边界和声学半空间下边界，使主介质梯形积分、底半空间导纳导数、模态符号选择、材料吸收扰动和群速度计算走过 Kraken 的常规路径。网格数固定在适合本地快速回归且足以稳定匹配模态的规模。环境名称、频率、声速剖面、密度、衰减、上下边界和相速度区间均写死在文件中，不依赖工作区外部输入。

测试运行时将此环境复制到各自的临时运行目录。原始环境文件保留在仓库，临时目录和生成的 MOD 文件保留在测试产物目录，避免两套程序覆盖同名输出。

## 组件与文件布局

- `for_test/fixtures/normalize/normalize_reference.env`：可版本化的基准环境。
- `for_test/normalize_kraken_compare.py`：运行 OOK、运行 Kraken、解析 MOD、计算指标并写入报告的测试驱动。
- `for_test/test_normalize_kraken_compare.py`：针对比较逻辑和完整对照流程的自动化测试入口。
- `for_test/artifacts/normalize_kraken/`：保留最近一次完整对照的输入副本、两端 MOD、标准输出、标准错误和 `comparison.json`。
- `tools/read_mod_summary.py`：复用现有 MOD 解析逻辑；不复制第二份格式解析器。

若构建系统不便直接调用仓库根目录外的 Python 工具，测试驱动通过明确的工作区根路径导入解析模块，并在路径无效时给出可诊断错误。

## 数据流

1. 测试驱动验证环境文件及 OOK、Kraken 可执行文件存在。
2. 创建相互隔离的 OOK 和 Kraken 运行目录，并复制同一环境文件。
3. 调用 `ook_case_runner.exe` 生成 OOK MOD，固定为单线程以降低运行差异。
4. 调用 `kraken.exe` 生成 Kraken MOD。
5. 使用同一解析器读取两份 MOD 的频率、网格、模态数、模态函数和复模态波数。
6. 先匹配模态波数顺序，再逐模态比较。模态函数允许全局符号相反；对每个模态选择 L2 差较小的 `+1` 或 `-1` 对齐方向。
7. 根据环境的声学层网格和密度，以 Kraken 使用的梯形积分口径重新计算每个模态的体积归一化积分，作为独立的归一化健全性检查。
8. 写出机器可读的 `comparison.json` 和便于复核的控制台摘要。

## 比较指标与通过条件

以下条件必须同时满足：

- 两端成功退出且均生成非空 MOD 文件。
- 频率、介质数、深度网格点数和模态数一致。
- 对应深度点最大绝对差不超过 `1e-6 m`。
- 对应复模态波数的最大绝对差不超过基于现有数值回归结果确定的固定阈值；首次红灯运行只用于测量实际差异，阈值不得为了让测试通过而高于已观察误差一个数量级。
- 模态函数完成符号对齐后，全局最大绝对误差或全局最大相对误差不超过 `5e-5`。相对误差忽略双方幅值均小于 `1e-10` 的近零样本。
- 每个被比较模态的体积积分为有限正数；对于此专用环境，积分与 1 的偏差使用固定的小容差判断，并在报告中记录最大偏差。
- 所有输出均为有限数，不出现 `NaN` 或无穷大。

比较报告同时记录前部、中部和尾部模态的逐模态误差，防止只检查低阶模态掩盖高阶模态偏差。

## 测试策略

实现遵循测试先行：

1. 先添加测试入口和环境文件，测试因比较驱动尚不存在或未产出报告而按预期失败。
2. 实现最小运行与比较驱动，使完整端到端测试通过。
3. 为符号翻转、近零相对误差、模态数不一致和非有限数值增加小型合成数据测试。
4. 运行比较测试、现有 MOD 工具测试和 OOK CTest 回归测试。

测试不得通过 mocking 替代 OOK 或 Kraken 进程。小型合成数据只用于证明比较器能发现错误，最终验收必须调用真实可执行文件。

## 错误处理与诊断

- 缺少可执行文件或环境文件时，报告明确列出绝对路径并失败。
- 进程超时时终止测试，保留已捕获输出并报告命令、工作目录和超时时间。
- MOD 解析失败时保留原文件并报告失败记录号。
- 网格或模态数不一致时停止逐点比较，但仍将双方元数据写入 JSON。
- 数值超差时返回非零状态，报告最差模态、深度索引、深度、绝对误差、相对误差及采用的符号。
- 测试产物写入前清理的范围只限于固定的 `for_test/artifacts/normalize_kraken` 目录；不删除其他测试或用户文件。

## 可复现性与交付物

最终交付包含专用 `.env` 文件、Python 测试驱动、自动化测试、两端原始 MOD 文件、进程日志和 JSON 对比结果。JSON 记录运行时间、可执行文件路径、文件哈希、阈值、模态统计和最差误差位置。

最终验证命令及实际输出摘要会在交付说明中列出。工作区已有的无关修改或删除项保持不变，不纳入本次提交。
