# OOK、Kraken 与 Krakenc 方案选型对比报告设计

## 目标

生成一份单文件、离线可打开的中文 HTML 报告，用于 OOK、Kraken 与 Krakenc 的方案选型。报告同时覆盖数值可信度、功能覆盖、运行性能、集成与维护成本，但保持中立，不给出唯一推荐方案。

## 受众与成功标准

- 受众：需要在三种实现之间做技术选型的研发、算法与项目负责人。
- 读者可在首页快速理解三者定位、主要差异和证据完整度。
- 每项结论可追溯到当前工作区的源码、构建配置、测试数据或既有报告。
- 实测事实、源码确认事实、历史报告结论和未验证项必须明确区分。
- 不以缺少适用案例或数据的项目作为失败项，也不以主观总分替代读者判断。

## 报告结构

1. 执行摘要：三者定位、关键差异和证据完整度。
2. 项目画像：语言、构建方式、接口形态、输入输出和依赖。
3. 算法与功能：求解路线、边界模型、衰减与散射、场与振速输出。
4. 数值可信度：OOK 与 Kraken 的现有验收结果、误差指标，以及 Krakenc 的证据缺口。
5. 性能与工程化：运行耗时、并发能力、可嵌入性、维护和测试成本。
6. 综合对比矩阵：按“强/中/弱/未验证/不适用”展示，不计算总分。
7. 场景适配：科研基准、工程集成、复杂介质和批量计算等场景的适用性与限制。
8. 附录：源码、测试产物和既有报告索引。

## 证据模型

报告使用四级证据标签：

- A 级：当前工作区在统一条件下得到的实测结果。
- B 级：可由源码、接口头文件或构建配置直接确认的事实。
- C 级：既有历史报告或说明文档中的结论。
- 未验证：没有同条件数据，或当前工作区不足以支持可靠判断。

结论只采用能够追溯的证据。性能对比尽量使用相同机器、相同计时口径和可适用的同类案例；不支持的案例标记为“不适用”。历史数据与当前复测结果冲突时，以当前复测为主，并说明差异。

## 数据采集与处理

1. 盘点 OOK、Kraken 和 Krakenc 的入口、核心模块、构建目标及依赖。
2. 从现有验收产物提取 OOK–Kraken 的成功率、TL 误差、振速结果和测试覆盖信息。
3. 检查当前可执行文件与用例，进行低风险的构建、运行和统一计时探测。
4. 将原始事实整理为内部对比条目，每条包含：维度、对象、结论、证据级别、证据路径和限制。
5. 将对比条目渲染为摘要卡片、矩阵、场景表、轻量图表与证据索引。

## 页面与交互

- 单文件 HTML，CSS 与 JavaScript 内嵌，不依赖网络资源。
- 响应式布局，桌面端优先，同时保证窄屏可读。
- 顶部提供摘要卡片与固定目录；主体使用卡片、表格和少量条形图。
- 支持“全部、已验证、未验证”筛选和章节跳转。
- 使用中文字体回退栈、清晰的证据徽标和色盲友好的状态色。
- 提供打印样式，打印时展开内容并隐藏交互控件。

## 异常与边界处理

- 构建或运行失败时保留命令、返回码和关键错误摘要，不把工具故障包装成产品能力结论。
- 某项仅适用于 Kraken 或 Krakenc 时标记“不适用”，避免横向误判。
- 无统一性能案例时只报告可确认的工程特征和各自测量，不给伪精确排名。
- 本地证据链接使用相对路径；无法稳定链接的证据以路径文本呈现。

## 验证

- 复核三种程序的名称、定位和 Kraken/Krakenc 算法差异。
- 核对表格中的每个数值与来源，避免重复引用旧结论为当前实测。
- 检查 HTML UTF-8 编码、内部锚点、筛选脚本和相对证据路径。
- 在桌面宽度和窄屏宽度下检查布局，并验证打印样式。
- 重新打开最终 HTML，确认页面无外部资源依赖和明显脚本错误。

- 辅助交付物：本设计文档和实施计划。
